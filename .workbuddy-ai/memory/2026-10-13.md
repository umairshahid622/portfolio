## Work Experience particle transition — spiral vortex rework
- File: `src/components/CharacterPointsCanvas.tsx` (both `BREAKDOWN_VERTEX_SHADER` and `POINTS_VERTEX_SHADER`, identical edits via replace_all)
- Problem: after the Skills section, the triangles flew from the skills spiral into the "Work Experience" particle text via a nearly-straight quadratic bezier — read as an unnatural "straight down" drop.
- Fix: replaced the bezier hand-off (branch `uExperienceProgress > 0.001`) with a spiral vortex path:
  - Each triangle orbits around the Work Experience title center: angle advances uniformly (`spiralTurns = 1.75`, same for all triangles for coherent arms), radius holds the full launch distance until ht=0.30 then collapses via `1 - smoothstep(0.30, 1.0, ht)` to exactly 0 at the glyc — guaranteeing pixel-exact assembly.
  - Two counter-rotating arms: seqP <= 0.5 ("SKILLS" glyphs) vs > 0.5 ("</>" glyphs) via `spinDir`.
  - Tighter launch stagger (`handoffStart = (1-seqP)*0.22 + |aRandom.w|*0.05`, was 0.40/0.06) so the whole stream winds as one spiral.
  - Kept Z-depth swoop and viewport clamp (released at handoffP 0.88).
- Continuity notes: position is exact at ht=0 (no launch pop); uniform turns + tight stagger avoid cloud smearing; assembly verified via headless Chrome screenshots at progress 0.15–0.90, assembled state, and reverse scroll-back.
- Verification: `npx tsc -b` clean; captured frames with playwright-core + system Chrome against `vite --port 5199` (lenis-driven page — must scroll via `page.mouse.wheel`, `window.scrollTo` is ignored).

## Work Experience transition — v2: extended spiral PATH (supersedes the vortex above)
- User feedback: the vortex still wasn't it. Requirement: **extend the spiral path itself down to the Experience section and let the particles travel ALONG that path on scroll**, then form the word.
- Final design in `src/components/CharacterPointsCanvas.tsx` (same file, both shaders via replace_all):
  - New shader helper `computeExperienceSpiralPath(rnd, u, viewport, time, cardYInfo, titleCenter)` defines ONE continuous thread:
    - `u ∈ [0, 0.42]` (`LOOP_SPLIT`) = the existing Skills loop (`computeSkillsSpringTarget(u / LOOP_SPLIT)`) — unchanged geometry.
    - `u ∈ [0.42, 1]` = an inward spiral centred on the title (screen centre), radius `r0 = |anchor|` decaying `pow(1 - vEase, 1.15)`, angle `th0 - 2π*1.75*vEase` (clockwise, continues the loop's exit tangent). Both segments meet exactly at the loop exit anchor, and radius → 0 at the title.
  - The spiral's **hub drifts** from the screen centre onto each mesh's own word centre (`settle = smoothstep(0.55, 1.0, vEase)`), so cream/gold unfurl into "Work" / "Experience" respectively while starting from an identical shared spiral.
  - Branch `uExperienceProgress > 0.001`: each triangle keeps a slot `uStart = seqP * 0.42` and marches `uNow = mix(uStart, 1, smoothstep(0,1,expProgress))` — spacing preserved, so the stream reads as one coherent ribbon. Glyph morph via `converge = smoothstep(0.55, 1.0, settled v)` driving `currentLocal` + `facetP`.
- Geometry facts measured live (1440×900): vH = 4.14, vW = 6.63, cardHalfH = 0.69, Ay = 1.34, cardCenterY clamps to 0.2 during the hand-off, so the loop exit anchor ≈ (1.88, 1.35) and the loop spans y ∈ [-1.14, 1.54].
- Gotchas learned: the Skills section is GSAP-pinned, so during the lead-in the cards slide up but `uCardYInfo` clamps — the loop/anchor stays stable. A coil whose axis merely interpolates anchor→title looks like a flat zigzag, NOT a spiral; a hub-centred inward spiral with a decaying radius is what reads as a spiral.
- Verified: frames at lead-in progress 0.15/0.30/0.45/0.60/0.75/0.90 + assembled + reverse scroll-back (desktop) and 0.30/0.55/0.80/1.00 (390×844 mobile); `npx tsc -b` and `npx vite build` both clean.
